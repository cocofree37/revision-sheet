# 修正依頼シート

Webサイト制作の課題管理表。クライアントがサイトを見て「ここを直してほしい」を書き込み、制作チームが状態を管理します。
静的ページ（`index.html`）＋ Supabase（データ保存）の構成で、GitHub Pages でそのまま公開できます。

## 使い方

1. 制作チームが「案件の管理」（`#/master`）を開き、マスターキーを入力して案件を追加します。
2. 案件ごとに **クライアント用URL** と **制作チーム用URL** が発行されます。
3. クライアントには「クライアント用URL」だけを渡します。URLを開くだけで使えます（ログイン不要）。

| | クライアント | 制作チーム |
|---|---|---|
| 依頼の登録・コメント・画像添付 | ○ | ○ |
| 「確認待ち」の依頼を完了／差し戻し | ○ | ○ |
| 状態・優先度・分類・担当・題名の変更 | ― | ○ |
| 依頼の削除・案件情報の編集 | ― | ○ |

## 機能

- 修正依頼の登録（クライアントの入力は「内容」「画像」「お名前」だけ。題名・分類・優先度は内容から自動で付与）
- 画像の添付（貼り付け・ドラッグ＆ドロップ・最大5枚、コメントにも可）と、画像への書き込み（四角・矢印・ペン・文字）
- ステータス管理（未対応 / 対応中 / 確認待ち / 完了 / 保留）と絞り込み・検索
- 依頼ごとのコメント（やりとり）
- CSV の書き出し

題名・分類・優先度の自動付与は、キーワードと文の切り出しによる簡易な判定です（AIではありません）。制作チームの画面から後で直せます。

## セットアップ（Supabase）

1. Supabase でプロジェクトを作成します。
   - Enable Data API：**ON** ／ Automatically expose new tables：**OFF** ／ Enable automatic RLS：**ON**
2. `supabase/schema.sql` の `__MASTER_KEY__` を、推測されにくい長い文字列（16文字以上）に置き換え、SQL Editor で実行します。
   - **置き換えた後のファイルは、GitHub にコミットしないでください**（マスターキーが公開されます）。
3. `index.html` 先頭付近の `CFG` に、Project URL と公開キー（Publishable key / anon key）を設定します。
   - `service_role` / Secret key は、絶対に書かないでください。

`CFG.anonKey` が空のときは、Supabase に接続しないデモモード（ブラウザ内保存）で動きます。

## セキュリティの考え方

- 4つのテーブルは RLS を有効にし、ポリシーを作っていません。公開キーでは **テーブルに直接触れません**。
- 公開しているのは `schema.sql` の関数だけで、各関数が **案件キー（推測できない64文字）** を確認してから処理します。
- 案件の作成とキー一覧の取得には **マスターキー** が必要です。
- 案件キーは「合鍵」です。URLを知っている人は誰でも入れるため、クライアント以外には共有しないでください。漏れた場合は、案件の管理画面から「キーを再発行」すると、古いURLは使えなくなります。
- 画像はデータベースに直接保存します（1枚あたり約250KB以下に自動で縮小。1件につき最大5枚）。
- ログイン機能・アクセス回数の制限・通知は、現在ありません。

## GitHub Pages で公開する

1. リポジトリを public にする（無料プランの場合）
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます
