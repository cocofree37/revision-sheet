# 修正依頼シート

Webサイト制作の課題管理表。クライアントがサイトを見て「ここを直してほしい」を書き込み、制作チームが状態を管理します。
静的ページ（`index.html`）＋ Supabase（データ保存）の構成で、GitHub Pages でそのまま公開できます。

## 使い方

1. 制作チームが「案件の管理」（`#/master`）を開き、マスターキーを入力して案件を追加します。
2. 案件ごとに **クライアント用URL** と **制作チーム用URL** が発行されます。
3. クライアントには「クライアント用URL」だけを渡します。URLを開くだけで使えます（ログイン不要）。

| | クライアント | 制作チーム |
|---|---|---|
| 依頼の登録・コメント・画像添付 | ○ | ○ |
| 状態・優先度・担当・題名の変更 | ― | ○ |
| 自分が書いた依頼・コメントの編集と削除 | ○（書いたのと同じブラウザから） | ○ |
| 他の人が書いた依頼・コメントの削除 | ― | ○ |
| 案件情報の編集 | ― | ○ |

## 機能

- 修正依頼の登録（クライアントの入力は「内容」「画像」「お名前」だけ。題名・優先度は内容から自動で付与）
- 画像の添付（貼り付け・ドラッグ＆ドロップ・最大5枚、コメントにも可）と、画像への書き込み（四角・矢印・ペン・文字）
- ステータス管理（未対応 / 対応中 / 確認待ち / 完了 / 保留）と絞り込み・検索
- 依頼ごとのコメント（やりとり）
- CSV の書き出し

題名・優先度の自動付与は、キーワードと文の切り出しによる簡易な判定です（AIではありません）。制作チームの画面から後で直せます。

## セットアップ（Supabase）

1. Supabase でプロジェクトを作成します。
   - Enable Data API：**ON** ／ Automatically expose new tables：**OFF** ／ Enable automatic RLS：**ON**
2. `supabase/schema.sql` の `__MASTER_KEY__` を、推測されにくい長い文字列（16文字以上）に置き換え、SQL Editor で実行します。
   - **置き換えた後のファイルは、GitHub にコミットしないでください**（マスターキーが公開されます）。
3. `index.html` 先頭付近の `CFG` に、Project URL と公開キー（Publishable key / anon key）を設定します。
   - `service_role` / Secret key は、絶対に書かないでください。

`CFG.anonKey` が空のときは、Supabase に接続しないデモモード（ブラウザ内保存）で動きます。

## メール認証（入場制限・制作チームのログイン）

パスワードは使わず、**メールに届くログイン用リンク**で認証します（Supabase Auth）。

- **クライアント用URLは、ログイン必須**です。ログインしていない人は、案件のデータを読めません（サーバー側で強制しています）。案件ごとに、入れる人の範囲を選べます。
  - 「ログインしたメールアドレスなら誰でも入れる」：案件のURL + ログイン。メールアドレスは、誰でもかまいません。
  - 「許可したメールアドレスの方だけ入れる」：案件のURL + 許可したメールアドレスでのログイン。新しく作る案件は、こちらが初期値です。
  - **制作チーム用URL**は、従来どおりログイン不要で開けます（案件の管理画面のみ、マスターキーまたは制作チームのログインが必要です）。
- **制作チームのログイン**：管理画面に登録したメールアドレスでログインした人は、全案件を「制作チーム」として操作できます（マスターキーがなくても、案件の管理ができます）。マスターキーは、最初の登録用として残しています。
- **セットアップ**
  1. `supabase/migrations/002_email_auth.sql`、続けて `003_login_required.sql` を SQL Editor で実行します（新規インストールは `schema.sql` に含まれています）。
  2. Supabase の Authentication → URL Configuration で、**Site URL** に、このサイトのURL（例：`https://<ユーザー名>.github.io/<リポジトリ名>/`）を、**Redirect URLs** に、同じURLの末尾に `**` を付けたもの（例：`https://<ユーザー名>.github.io/<リポジトリ名>/**`）を登録します。メールのリンクを開いたあと、このサイトに戻るために必要です（未設定だと `localhost:3000` に飛びます）。
  3. 管理画面（マスターキーで入れます）で、制作チームのメールアドレスを登録します。
- **メールを日本語にする**（この案件では設定済み）：Supabase の標準メールは英語で、文面は編集できません。独自の SMTP（Resend、Google Workspace など）を設定すると、Authentication → Emails → Templates で文面を編集できます。日本語の文面は、次のファイルに用意しています。
  - `supabase/email-templates/magic-link.html`（「Magic link or OTP」に貼り付け）
  - `supabase/email-templates/confirm-signup.html`（「Confirm sign up」に貼り付け。初めてのメールアドレスには、こちらが使われます）
- **リンクが「無効または期限切れ」になるとき**：リンクは一度しか使えません。メールソフトによっては、リンクの安全確認のために、先にリンクを開いてしまい、無効になることがあります。その場合は、もう一度送り、届いたらすぐに開いてください。

- **メール送信の制限**：Supabase の標準メールは、送信できる宛先が Supabase のチームメンバーに限られ、送信回数も少ない（1時間に数通）ため、動作確認用です。実際のクライアントに届けるには、Authentication → Emails → SMTP Settings で、独自の送信サービス（Resend など）を設定してください。

## セキュリティの考え方

- 4つのテーブルは RLS を有効にし、ポリシーを作っていません。公開キーでは **テーブルに直接触れません**。
- 公開しているのは `schema.sql` の関数だけで、各関数が **案件キー（推測できない16文字）** を確認してから処理します。
- 案件の作成とキー一覧の取得には **マスターキー** が必要です。
- 案件キーは「合鍵」です。URLを知っている人は誰でも入れるため、クライアント以外には共有しないでください。漏れた場合は、案件の管理画面から「キーを再発行」すると、古いURLは使えなくなります。
- 画像はデータベースに直接保存します（1枚あたり約250KB以下に自動で縮小。1件につき最大5枚）。
- 書いた人だけが編集・削除できるように、ブラウザごとに **本人確認用の合言葉**（ランダムな文字列）を作り、書き込みに紐づけています。サーバーには合言葉そのものではなく **ハッシュ値だけ** を保存します。
  - 別のブラウザ・端末、またはブラウザのデータを消した後は、自分が書いた分でも編集・削除できなくなります（制作チームは削除できます）。
  - 案件キーを知っていても、他人の依頼・コメントは編集できません（制作チームによる削除のみ可能）。
- ログイン機能・アクセス回数の制限・通知は、現在ありません。

## GitHub Pages で公開する

1. リポジトリを public にする（無料プランの場合）
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます
